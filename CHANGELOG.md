### Added

**Fidelity, privacy, and trust**

- **Byte-faithful round-trips** — untouched lines are preserved exactly, and constructs the editor can't re-emit byte-for-byte (reference links, wikilinks, callout markers, tight lists, Notion asides) are pinned to their saved bytes, so editing one part of a file never rewrites another.
- **Content-conservation guard** — a move, duplicate, drag, or table reorder that would silently lose or corrupt content is blocked outright, with a quiet notice instead of vanishing text; drops can't land inside hidden or collapsed content. The same protection covers what a *save* would do to the result: a move or drop whose outcome wouldn't survive saving and reopening — nesting one Notion `<aside>` inside another used to silently delete the inner one's text from the file a save later; moving a directive below a stray unclosed `:::` line permanently flattened it — is quietly declined instead. A document that already carries such damage still edits normally; only a gesture that would *add* damage is refused.
- **Offline by default, with a single master network switch** — every feature that could contact the network (paste-unfurl, URL embed players) sits behind `birta.network.enabled`, which ships **off**: out of the box the editor makes no outbound request (the content-security-policy pins the few named provider hosts a card *may* use, but with the switch off nothing is built that could request from them). Turning it on enables both features (each still has its own on-by-default switch). You don't have to find the setting first — the moment you do something that would use the network, a quiet, dismissable "Enable" prompt appears where you're working; dismissing it stops the prompt for the session. Enabling — from the prompt, the setting, or the **Toggle Network Features** palette command — takes effect immediately in every open editor, no reload needed: pending unfurls complete and embed cards render in place.
- **No network egress for document content** — images are always saved to the local workspace and never uploaded; remote image loads are blocked, opened URL schemes are allowlisted (`javascript:` / `file:` / `command:` are blocked), the HTML sanitizer is hardened, and Mermaid runs in strict mode. The editor has no path to send document content off the machine.
- **Send Feedback — a way to reach the maintainer that isn't telemetry** — a **Send Feedback** command in the palette asks what the issue is, optionally how you'd feel if you could no longer use Birta, optionally any further detail, and where it should go: a prefilled GitHub issue, a prefilled email to Birta Labs, or the clipboard. **Birta never sends it: you do.** It composes text and hands a URL to your browser or mail client, so the report goes under your own identity, into a draft you can still read and edit before pressing Send — which means the command works with `birta.network.enabled` off, needs no account with us, and adds no consent setting, because there is nothing to consent to. The destination step says what each choice costs, so a GitHub issue's account requirement is something you learn before you're standing at a login screen holding your report. It never asks first: no prompt, no nag, no rating popup — the palette is the only way in. The report carries your Birta and VS Code versions, your OS, and which `birta.*` settings you've changed from their defaults, in a collapsed block you can delete before sending; a setting's *value* is included only when it can't be a path or a sentence (so `birta.customCss` reads "2 entries", never your paths), and your document, its file path, and your workspace name are never included at all. Your clipboard is left alone unless you choose it, or unless something goes wrong: if the draft can't be opened, or the report was too long for the link, the full text is copied there and Birta tells you so.
- **A disk-drift badge** warns when a file open with unsaved edits is changed on disk by another tool — a terminal, git, an AI assistant: reload from disk or compare the two versions side by side. The editor never silently overwrites or merges.
- **Crashes surface instead of going silent** — if the editor's rendering layer hits an unexpected script error, VS Code now shows an error notification (deduplicated, capped per session) rather than the editor quietly stopping; your document and its native save path are unaffected either way.
- **Restore Previous Content** — a last-resort recovery command. If a single editor update ever removes a large share of a document's lines (a mass delete, or an editor defect slipping past the other safeguards), the extension quietly keeps the prior text in memory; **Birta Writer: Restore Previous Content** swaps it back — running it again swaps back the other way. The kept text survives closing the editor tab (not a VS Code restart), and nothing is written anywhere or sent off the machine. VS Code undo and hot exit remain the primary recovery paths.

**Editing**

- **WYSIWYG Markdown editing** — open a `.md` file as rich text and save standard Markdown back. The editor is backed by a real VS Code text document, so it carries native dirty state and saves through VS Code's own `files.autoSave` / Cmd+S with no separate save timer. Toggle to Raw Markdown and back at any time; switching with unsaved edits shows the normal Save / Don't Save / Cancel prompt.
- **Block handles and the block menu** — every block, at every nesting depth (including inside callouts, quotes, and directives), has a gutter handle. Click it for a menu — turn into another block type, duplicate, copy as Markdown, copy link, move up/down, delete — or drag it to reorder; a heading carries its whole section. Open the same menu from the keyboard with ⌘. / Ctrl+. Resting visibility is set by `birta.blockHandles` (`always`, `headings` — the default — or `hover`), also reachable from the toolbar's display (A) menu.
- **Block selection and keyboard editing** — select whole blocks with an Escape ladder (caret → block → all document), Shift+↑/↓ to extend, or a rubber-band marquee dragged in the margins; move them with Alt+↑/↓, duplicate with ⇧⌥↑/↓, delete with ⌘⇧K. Plus the VS Code editing canon adapted to WYSIWYG: join lines, insert a paragraph above/below without splitting, transform case, and a smart expand/shrink-selection ladder.
- **Folding** — fold headings, callouts, nested list items, tables, and code blocks from a gutter chevron (or the Fold / Unfold / Fold All commands, ⌘⌥[ / ⌘⌥]). Chevron visibility follows VS Code's own `editor.showFoldingControls` / `editor.folding`. Folds persist per tab and never touch the file — or write an Obsidian `[!kind]-` marker explicitly from a callout's menu when you want the collapsed state saved.
- **Slash command menu** — type `/` to open a filterable, keyboard-first insert menu (text, lists, and insert blocks) with the markdown shortcut shown for each row. Filtering matches label and keyword prefixes, substrings, and compressed word-prefix abbreviations (`/seclink` finds **Section Link**, `/inlmath` finds **Inline Math**). It's context-aware and runs the same commands as the toolbar and command palette.
- **Find and replace** — a find bar with ⌘D occurrence cycling, Change All Occurrences (⌘F2, also ⇧⌘L), Find in Selection — which shades the range it is scoped to — and Match Case / Whole Word / Regex toggles. It skips code blocks and diagrams that are showing their rendered preview, so a match never lands on hidden source.
- **Inline calculator** — type an arithmetic expression with an equals sign at *either* end (`12 * 4 =` answers after it; `=5+7` answers before it, as `12=5+7`) and the result is offered as a suggestion you confirm with Tab (Return stays free to start a new line); an **Always insert result** row in the menu — also the **Toggle Calc Auto-Insert** palette command, `birta.calc.autoInsert` — switches to insert-on-`=` from then on. Everything inserts as plain text, so the file stays ordinary prose. Supports `+ - * /`, `%` (modulo), `^` / `**` / superscript digits (exponent), parentheses, decimals, and unary minus — plus the Unicode operator glyphs `×`, `÷`, `·`/`⋅`, and `−`, and a lone `x` between numbers as multiplication (`2 x 3 =`, `1024x768 =`); only pure arithmetic is evaluated — `x` is the single letter admitted, and only as an operator — and detection refuses any run that would compute a *different* question than the visible one, offering nothing over a wrong answer. Answers are honest or absent: rounded for display (at most 6 decimals, float noise never leaks), refused when they can't print truthfully. An existing `expr = answer` stays maintained: edit the expression and the answer updates in place, advisory mode included (advisory maintenance leaves a result followed by prose alone — `Dec 24-26 = 3 days off` is annotation, not an equation — while auto-insert keeps full reach), and editing the *answer* is always your override. On by default (`birta.calc.enabled`); the menu's footer points at the richer `=>` form.
- **Living calculations with `=>`, variables, and units** — type an expression followed by `=>` (`rent / budget * 100 =>`, `3 km in mi =>`) and the answer is offered for Tab, written as `expr => result` in plain text. Expressions can reference **named variables** defined earlier in the document as `name = value` lines (several may share a line: `a=5, b=2`), resolved top-to-bottom — only definitions *above* the line count. They can use **functions and constants** (`sqrt`, `abs`, `ln` / `log10` / `log2`, `exp`, trig in radians and inverses, `round`/`floor`/`ceil` — a bare `log(…)` deliberately computes nothing, because half the world's calculators read it as base 10 and half as the natural log; the menu offers both readings with their values and writes your pick into the equation; `pi`/`π` and `tau`/`τ` — your own definition of a name always wins, and Euler's `e` is deliberately *not* a constant), **superscript exponents** (`c²` is `c^2`), and **offline unit conversions** with `in` / `to` across the full mathjs catalog — length, mass, time, volume, temperature, area, data, and more — all computed locally by the same safe, eval-free engine as `=`; the lazily-loaded unit catalog never sees your expressions, and currency is deliberately absent (live rates would need the network). A few units side with the note-taker over the catalog's convention: kitchen spoons are US customary (1 cup = 16 tbsp), and `1 year in days` is 365 — not the Julian 365.25 — with a year being exactly 12 (average) months and decades/centuries following suit; write `365.25 days` when you mean the astronomical year. Accepted answers stay **alive**: edit the expression, or a definition above it, and every dependent result updates in place; delete or rename a definition away and its dependent answers are *withdrawn* (the line reads `expr =>` again) rather than left stale — one undo restores everything, editing a *result* is always your override, and anything inside backticked code is source, never touched. Governed by `birta.calc.enabled` for the inline forms; fenced ` ```calc ` blocks have their own independent switch.
- **Stale and broken living-calc answers are visibly flagged** — when an accepted `=>` answer stops matching the document and the editor deliberately won't rewrite it (the definition changed in the raw editor or a git checkout, the equation was moved above its definition, or the file arrived that way), the answer number now carries a quiet cue instead of standing as a silent lie: a faint warning-tinted highlight means *stale* (the expression now computes a different value), and the same tint with a strikethrough means *broken* (it no longer computes at all — a vanished definition, a `1/0`, a `km`-to-`kg` conversion). Click the number for the explanation and the actions: **Update** rewrites it to the fresh value, **Remove answer** takes the number off (leaving `expr =>`, ready to re-answer), **Ignore** silences that equation for the session (when a proofreading finding covers the same text, one popup stacks both, the cue first) — nothing touches the file except those clicks, each a single undo step. Only answers with an outside premise are ever flagged: plain `=` equations and constant-only arrows (`2+3 => 6`) are yours, hand-edited or not, and a definition you're mid-way through retyping never flags its dependents. The scan runs on idle after the editor is interactive; with `birta.calc.enabled` off it costs nothing.
- **Self-sinking checklists** — turn on **Move checked tasks to bottom** (a switch in the toolbar's Lists menu, a toggle row in a task list's block menu, a palette command, or `birta.checklist.sinkChecked`) and checking a task-list item moves it below the still-unchecked items in the same list (with a brief highlight where it lands); unchecking floats it back up to the bottom of the unchecked group. A parent item carries its nested items with it, one undo restores the previous order, and only existing list lines are reordered — though moving an item that has nested children can re-serialize that list in loose (blank-line-separated) form, the standard Markdown equivalent. Off by default — the checkbox otherwise flips in place. An **Uncheck All Tasks** command (command palette, and the block menu of a task list) clears every box in the whole checklist — nested sublists included, from whichever level you invoke it — in one undo step.
- **Backtick wraps a selection in inline code** — with text selected, pressing `` ` `` toggles the inline-code mark over it instead of replacing it with a literal backtick, matching what ⌘E, the toolbar, and the slash menu's `` ` `` hint already did. Press it again to un-code. With nothing selected the backtick is unchanged, so typing a `` `code span` `` the ordinary way still works.
- **Floating selection palette** — selecting text raises a small formatting bar just above it (bold, italic, strikethrough, inline code, link, and a copy-for-AI-agent button), lighting the buttons for marks already applied; a paragraph/heading turn-into appears only when the whole block is selected. Four more buttons — inline math, highlight, link to section, clear formatting — ship hidden to keep the bar small; opt any of them in via `birta.floatingToolbar.items.*`. Works for mouse and keyboard selections alike; selecting whole blocks raises move / duplicate / delete instead — the first mouse affordance for a multi-block selection. It follows its text as the view reflows, its Link button drives the same link editor as the toolbar and ⌘K, and the bar steps aside when the link editor or block menu opens. Turn it off with `birta.floatingToolbar.enabled`, or hide individual buttons with the same `birta.floatingToolbar.items.*` settings.
- **Tighten / Loosen List** — a list item's block menu offers one toggle for the whole list's spacing: **Tighten List** removes the blank lines between items (keeping any blank line Markdown requires, like a multi-paragraph item), **Loosen List** adds them everywhere — nested sublists follow, one undo step either way. This is the deliberate counterpart to the editor's hands-off rule (see Fixed: spacing is never rewritten as an edit side effect), and it matters beyond the source bytes: loose items render with paragraph spacing in most Markdown pipelines.
- **Merge adjacent lists on demand** — when a document carries two same-kind lists back to back (Markdown's `-`/`*` marker-change syntax — often left behind by past editing rather than written deliberately), the editor offers to make them one list instead of guessing: with the caret in the first item of the lower list, a quiet inline suggestion — the inline calculator's pattern — offers **Merge with list above** (Tab confirms, Return keeps its newline meaning, Escape dismisses), and any item's block menu offers **Merge with List Above / Below** rows whenever a same-kind neighbor exists (hidden otherwise). Either way the merge is one undo step. Splits *created by your own edits* never need this — they merge automatically (see Fixed).
- **Browse for a link target with the OS file picker** — the link editor's URL field gains a folder button that opens your system's native file dialog, anchored at the document's own folder. The picked file lands in the field as a document-relative path — exactly what you'd have typed by hand — with the resolved-target hint confirming where it opens; nothing is written to the document until you confirm with Enter or click away, same as a typed edit, and canceling the dialog changes nothing. Complements the inline path autocomplete for targets you'd rather find than type — deep trees, images, non-markdown files.
- **Paste Markdown as Markdown** — pasting plain text that carries Markdown syntax now becomes real nodes: `# Title` is a heading, `- item` a list, `**bold**` bold. Previously that text landed literally and the syntax was escaped back out on save (`\# Title`), which meant the editor could not even read back what its own Copy had put on the clipboard. Pasting from a browser or a word processor is unchanged — rich content still keeps its own formatting — and a paste inside a code block is always literal, so a fenced block never reinterprets its payload. A lone block pasted mid-sentence still merges as text (pasting `# Title` into prose must not split a heading into it); it becomes a heading when it lands on an empty line. **Paste as Plain Text (⇧⌘V)** pastes literally for one paste — also a command in the palette, so it's reachable and rebindable like any other; `birta.pasteFormat` set to `plainText` makes every paste literal — the mirror of the existing `birta.copyFormat`. **Pasting into a table cell keeps the table's shape**: a GFM cell holds only inline content, so pasted blocks land as the cell's lines joined by line breaks instead of widening the table with junk columns (the old literal behavior — two pasted lines turned a 2-column table into 5) or splitting it into fragments.
- **Pasting multi-line text into a heading keeps it one heading.** The lines join with a space, as a heading has no way to hold a line break; previously the break was written into the file as a real newline, so reopening the document split the heading in two.
- **Pasting an image from a browser inserts one image, not two.** An image copied from a web page carries both the picture and its HTML markup, and the editor was inserting both — a broken one pointing at the original web address, and a second with the saved file but no description. Now it saves the file once and keeps the description from the page you copied it from.
- **A pasted or dropped image shows that it's saving — and says so if it fails.** Saving an image is a round trip to disk (dedup, then write it next to your document), and until it returned the editor said nothing: no sign the paste had registered, and no sign at all if the save failed. A quiet inline pill marks the spot while the save runs — only if it takes long enough to be worth saying (a fast local save stays silent rather than flickering) — and a failure becomes a dismissable message naming the reason, right where you pasted. Both are display only — a failed save leaves your document exactly as it was, with nothing to clean up and no stray undo step. The image also now lands **where you pasted it** rather than wherever the cursor happened to be when the save finished, so you can keep typing while it saves.
- **Rich HTML pastes keep more of what you copied** — pasting from a browser, Google Docs, or Word already converted to Markdown; three kinds of marked-up content were being silently dropped on the way and now survive: **strikethrough written as `<s>`** (only `<del>` was recognized, so `~~text~~` copied out of most renderers arrived as plain text), **task-list checkboxes** (a rendered checklist from GitHub or Notion pasted as plain bullets with every tick lost), and an **image's title is no longer invented from its alt text** — an ordinary `<img src alt>` used to gain a hover tooltip the source never had, written into your file.
- **Copy as Rich Text** — a new command (command palette and the right-click Copy group) that puts a real rich-text (HTML) clipboard entry on the clipboard from the selection — or the block under the pointer — so rich editors like Docs, Word, or an email compose paste real formatting. **Copy as Markdown** joins it in the command palette. Each copies its named format regardless of the `birta.copyFormat` setting, so either is one command away for a one-off copy.

**Blocks and syntax**

- **Tables** — Google-Docs-style overlay chrome (row/column grips, hover insert bars, drag-to-reorder) and per-column alignment (left / center / right) with GFM markers that round-trip faithfully.
- **Callouts, admonitions, and directives** — GitHub alerts (`> [!NOTE]` …), Obsidian callouts (per-kind icon and accent, collapsible bodies, aliases, fold markers), Docusaurus `:::name` container directives, and Notion `<aside>` exports all render richly with editable titles. Insert from the slash menu, the command palette, or by typing `[!note] ` / `:::name `. Callout types nest, and every marker line round-trips byte-for-byte.
- **Math** — inline `$…$` edits in place like inline code (the caret walks into the raw LaTeX and it re-renders on exit), plus `$$…$$` math blocks. KaTeX loads on demand.
- **Mermaid diagrams** — render on a white canvas by default so they stay legible in dark themes (the way GitHub and Notion present them); `birta.mermaid.theme` chooses `light` / `dark` / `auto`. The engine loads on demand.
- **Calculation blocks** — a fenced ` ```calc ` block (insert from the slash menu's **Calculation Block**, or the language picker's **Calculation** entry; ` ```calculation ` works as an alias) is a live worksheet: every line is computed under one shared, top-to-bottom scope and shown in a two-column ledger — source on the left, value on the right — that recomputes as you type. Define variables with `name = value` and reuse them below (`budget = 5000`, then `budget * 0.3`), do offline unit conversions across the full mathjs catalog (`3 km in mi`, `1 GB in MB`), and annotate with `#` / `//` comment lines. A bare number or prose simply shows no value, while a line that *reads* as a formula but can't compute — an unknown variable, a `1 / 0`, a `3 km in kg` dimension mismatch — shows a quiet dimmed dash so a typo is visible without being loud (prose compounds like `T-1000` or `state-of-the-art` never trip it). A rounded value offers its full-precision number as a hover tooltip. The ledger's text is selectable and copies sensibly (`source`, then `= value`), its values follow the content text-size stepper, and clicking it parks the editor — keystrokes never land at an invisible caret elsewhere in the document. The source is never rewritten — results live only in the rendered view — so the block round-trips byte-for-byte as ordinary Markdown, and toggling to code shows exactly what you typed. Same deterministic, offline, `eval`-free engine as the inline `=` and `=>` calculators, but on its own switch: `birta.calc.blocks.enabled` (on by default), independent of the inline `birta.calc.enabled` — so a worksheet keeps computing even with inline calc silenced, and vice versa.
- **Highlight** — `==marked text==` (Obsidian) renders as a theme-aware highlight.
- **Images** — alt text shows as an editable caption under the image, the title as a hover tooltip, and the file path edits from a filename chip in the image toolbar (applied on blur). The image's key actions — zoom, width, delete — live in a control column at the image's top-right (hover-revealed, pinned open while selected), the same anatomy as embed cards, tables, and code blocks.
- **URL embeds** — a bare provider link on its own line renders as an inline card, for five providers: **YouTube** (a static thumbnail with a play button that loads the actual player only when you click it, through the privacy-mode `youtube-nocookie.com`), **Vimeo** (the same click-to-load card; its player always loads with `dnt=1`, Vimeo's do-not-track flag), **Loom** (the same click-to-load player behind a quiet branded facade — no thumbnail is fetched, so nothing loads until you press play), **Figma** (design files, FigJam boards, slides, and prototypes in a taller frame that loads the live Figma embed on click), and **GitHub** (a compact info card for a repo, pull request, issue, or file, built **from the URL alone** — zero network, so it renders even with the network switch off). Every card is **display only** — the source stays the plain link, so the file round-trips byte-for-byte and turning embeds off simply shows the link again. Cards are **first-class blocks to edit around**: arrow keys stop at each card with a selection ring (sequential cards are each their own stop, never skipped), clicking a card selects it, and selecting opens a small **palette** with the editable URL plus open / copy / **show as text link** / delete verbs — Enter edits the URL in place, and Backspace next to a card selects it first so a second press deletes it cleanly instead of silently merging the hidden URL into your prose. Each player card carries a resident **identity strip** just below the frame — the **page title** (fetched from the provider's own oEmbed endpoint when network features are on; display-only, never written to the file) over the **URL** — visible at all times, playing included, with the edit palette taking its place while open; branded facades name their service in the frame's corner. Click semantics split by surface: **anywhere on the media area loads the player** (Figma's is an explicit "Load Figma preview" pill rather than a bare glyph), while **the identity strip selects the card** and raises the palette; on a selected card, **Space toggles play/stop** from the keyboard. Players are stable and reversible: a **stop button restores the facade**, the open-in-browser button survives playback (an in-editor player depends on the provider accepting the embed context while the external path always works), and editing elsewhere in the document no longer restarts a playing video. The control column **beside** the frame (never over it — an embedded player owns its own corners) carries six verbs — stop (while playing), **open in browser**, **full width / fixed width** (this card's own span, see *Per-block width*), and **fullscreen** (the player in a lightbox overlay — same click-to-load consent and the same sandbox containment as the inline player; Escape, the close button, or a backdrop click dismisses it), then, after a small gap, the edit pair: **edit** (a toggle: opens the palette on the URL, closes it again) and **show as text link** (converts the card back to a labeled link) — each with a tooltip that opens over the embed, clear of the next control. Cards center in the content column. The conversion runs both ways: hovering a labeled link whose URL could card (a provider link alone on its line) offers **Show as embed** in the link popup, restoring the card — selected, so it renders immediately — in one click. Facades identify their service by **name in text** rather than approximated logo glyphs. Players load **without forced autoplay** — a webview can't delegate its click into a provider's iframe, so requested autoplay just blocked and spun on a black frame; the facade click now loads the provider's real player and its own play button starts it reliably. Failure states are visible instead of blank: a dead video's thumbnail degrades to the branded facade, and a Figma preview that needs sign-in gets a persistent, **clickable notice inside the frame** that opens the file in Figma directly. (Figma embeds render at all now: Figma's embed host silently redirects into `www.figma.com`, which the editor's content-security-policy blocked — every Figma card was a blank frame until that host was allowed.) Cards render on an idle pass after the editor is interactive, never blocking first paint. Offline by default: the master network switch `birta.network.enabled` gates every card that would make a request (thumbnail or player), while the request-free GitHub card needs only the feature's own `birta.embeds.enabled` (on by default) — with the master off, nothing is requested from anywhere. Either switch takes effect **immediately in every open editor**, with no reload, and pasting a link that can become a card never fetches a title for it — the card is the answer for those links.
- **Links and wikilinks** — one link editor for both inserting and editing (⌘K, or click a link; applies on blur; a Markdown / `[[wiki]]` format switch). Editing the link text previews live on the page as you type — whether editing an existing link or linking selected text with ⌘K; Escape puts the original back exactly, Enter or clicking away keeps it — and the editor widens for real-length URLs and titles. The URL field suggests the document's own headings — type `#` to browse them all, or just part of a heading's title or slug and the matching anchors appear alongside file matches (no `#` required) — so an internal section link is two keystrokes away. Wikilinks (`[[target|alias#heading]]`) round-trip byte-identically with bare-name autocomplete. **Smart link resolution** (`birta.smartLinks`) opens local links the way a site generator would publish them — workspace-root paths, content-root inference, `index.md` / `_index.md` suffixes — and shows the resolved target while you edit. **Link to a section** — type `#` after a space anywhere in prose and a dropdown of the document's headings opens, narrowing as you type (the typed `#query` shows as a filter chip, exactly like the slash menu); pick one with arrows + Enter/Tab and it becomes a standard `[Heading title](#slug)` anchor link, or just keep typing — the menu never captures plain typing or inserts on its own, even when what you typed exactly matches a heading (a line-start `#` still means a heading and never triggers it). The same flow starts from the slash menu (`/section`, which also answers to *header*, *heading*, and *anchor*), the selection palette's own button, or the Link to Section command; with text selected, a picker list appears instead and the selection becomes the link text. The anchor targets the same GitHub-style slug (duplicate headings included) the in-page jump resolves. **Pasting a URL over selected text links the selection** instead of replacing it, opening the editor prefilled to confirm or fix it — one undo removes the link. Detection is narrow: full URLs (`https://…`, `mailto:…`) and bare web domains (`example.com`, `www.foo.com/path`) link; plain text, a file path or bare filename (`notes.md`, `app.ts`), a version tag (`v1.2`), or a markdown/wikilink snippet still replaces the selection, and a paste inside a code block, over an existing link, or across blocks is never intercepted.
- **Section links follow a heading rename** — rename a heading and every same-document `[text](#slug)` anchor link pointing at it is repointed to the heading's new slug automatically, in the same undo step (one Cmd+Z restores the heading text and the links together). Only the link's target slug changes — the link text is left alone and the file round-trips as ordinary Markdown; duplicate-heading `-N` slugs are kept consistent (renaming the first of two `Foo` headings updates links to both). Moving a heading without changing its text rewrites nothing, and a link to a heading you delete is left exactly as typed and flagged **Heading not found** in the link popup rather than silently repointed. On by default (`birta.autoUpdateAnchors`); turn it off to leave anchor links untouched when a heading's text changes.
- **Paste a bare URL to get a titled link** — with nothing selected, pasting a bare URL (`https://…`, or a bare domain like `example.com`) inserts a link and, when network features are enabled, fetches the linked page's title and **offers** it as the link text. The link appears instantly; a moment later the title arrives as a small prompt at the link — take it and the link becomes `[title](url)`, ignore it and the plain link stays. **Nothing is written to your document until you accept**, because a network reply landing seconds after you paste shouldn't quietly edit your file; `birta.pasteUnfurl.autoApply` (off by default, also offered as an "Always use fetched titles" row on the prompt itself) switches to applying titles the moment they arrive. The fetch requests only the URL you pasted, reads the page's title from its HTML (no third-party service), and keeps the plain link when the page is offline or untitled; it refuses local and private-network addresses outright (localhost, `192.168.*`-style ranges, cloud metadata endpoints) and re-checks every redirect against the same rule, so a pasted link can only ever reach the public web. Offline by default: with the master network switch `birta.network.enabled` off — the default — the paste inserts a plain link and makes no request, and a quiet, dismissable prompt appears at the link offering to turn network features on. The feature also has its own `birta.pasteUnfurl.enabled` (on by default). A link that renders as an embed card is left to the card instead of being retitled. Pasting a URL *over selected text* still links the selection as before, and detection stays narrow (a file path or `notes.md`-style name is never treated as a URL).
- **Frontmatter panel** — YAML metadata edits as a borderless key/value grid; list values become removable chips with workspace-wide autocomplete; the panel collapses (`birta.frontmatterExpanded`) and has full keyboard, undo, and screen-reader support. A document *without* frontmatter opens with no panel at all by default — the file starts where the file starts. Turn on `birta.frontmatterAddButton` (or the **Toggle Add Metadata Button** command) and such a document instead shows a quiet **Add metadata** button in the panel's spot, which shifts the content down by one button row: committing the first field inserts the fenced block at the top of the file, while abandoning the empty row leaves the document untouched and the button back in place. Either way the **Edit Frontmatter** command starts the same flow, and either way a document that *does* have metadata shows its full panel — the setting governs only the frontmatter-less state, and applies to open editors immediately.

**Layout and appearance**

- **Customizable toolbar** — show, hide, and reorder every item (`birta.toolbar.items.*`), or hide the whole bar for a chrome-free surface; hidden actions stay reachable from the slash menu. Quote, Lists, and Code dropdowns group related inserts, and the bar highlights whatever the cursor is in.
- **Typography** — sans / serif / mono font presets with customizable stacks and a content font-size stepper (`birta.fontPreset`, `birta.fontFamily*`, `birta.fontSize`), plus a Full-Width / Fixed content-width control (`birta.contentWidth`, `birta.maxContentWidth`).
- **Per-block width and centering** — embed cards and standalone images center in the content column, and every embed card, image, code block, and table carries its own **Full Width** toggle: the block spans the whole pane — breaking out wider than a Fixed-width page's column, to exactly the span the toolbar's page-level Full Width setting would give it — while the rest of the document keeps the column. The toggle lives in each block's **control column at its top-right** (images cycle **natural size → fit column width → full width**, so a small image is never blown up unasked); tables also offer a **Full Width** row in their block menu. When the page itself is in Full Width mode, the table/code toggles (and the image cycle's redundant third step) disappear rather than sit there as dead switches — a control only shows where it changes something; the embed toggle stays, since its Fixed state is a real size cap in either page mode. Top-level blocks only — a block nested in a list or quote isn't the column's width to begin with. The choice is presentation-only and the Markdown never changes (no HTML wrappers, no attributes — the file round-trips byte-for-byte); widths persist per document **and per workspace** — like VS Code's own per-file view state, they survive switching to the raw editor and back, window reloads, and full restarts — keyed to the block's own content (an embed's URL, an image's path, a code block's first line, a table's header row), and a width whose block no longer matches simply falls back to the default. The same durability now covers folds, scroll position, and the frontmatter collapse, which previously could silently reset across a raw-editor round trip.
- **One control column for every rich block** — embed cards, images, tables, and code blocks all put their key actions in the same place: a vertical column of icon buttons just outside the block's top-right corner, hidden at rest — a run of small blocks never paints a strip of buttons down the margin. The whole band to the block's right is the hover target (no precision mousing), and the column stays visible while you're **in** the block: a caret inside a table cell or a code block, a selected embed or image, all pin their controls open. One order everywhere: the block's primary verb first (open / zoom / copy), then view controls (preview, word wrap, width, fullscreen), then editing verbs; no delete buttons — deletion belongs to the block menu and the keyboard. A code block's word-wrap toggle is now a **remembered per-block choice** (it used to reset every time the block re-rendered): an overridden block keeps its wrap across reopens, while an untouched block keeps following the `birta.codeBlockWordWrap` setting. A persistent tint marks only the toggles whose state isn't visible in the content (full width on, word wrap on) — mode switches like code ⇄ preview don't tint. Fullscreen is one verb everywhere: the same diagonal-expand icon on images, embeds, code, and diagrams, and every fullscreen *preview* (image, embed player, diagram) opens over the same theme-aware translucent wash — no more always-dark photo scrim on one of them (the code editing sheet stays opaque, it's an editor, not a preview). On a short block the column overflows below the block at full size instead of squashing its buttons. The display-as pair got honest icons (the Confluence/Notion vocabulary): **show as text link** is text lines, **show as embed** is a card. Code blocks lost their header bar for it: the language pill and the fold `…` chip float inside the canvas's top-left (the code shifts down so the first line never hides under them). Floating palettes (the selection formatter, link popup, and image path/title chip) now sit on a subtly offset surface so they read as chrome over the page instead of blending into it. In the display (A) menu, the width control now sits above the text-size stepper.
- **Block rhythm** — every rendered set-piece breathes: embed cards, tables, standalone images, callouts, code blocks, and rendered raw-HTML blocks get generous vertical room (1.5em above and below, top level only — lists and callout interiors keep their compact rhythm), and horizontal rules carry an equivalent band with the line through its middle — a section break reads as a pause rather than a hairline squeezed between paragraphs, and it's a far easier click target.
- **Width flips keep your place** — switching the page between Full Width and Fixed (from the toolbar, Settings, or another editor) re-wraps the whole document; the top visible line now stays the top visible line instead of the text jumping to a different scroll depth.
- **Word count in the status bar** — words, characters, and estimated reading time for the active document show in the status bar and update as you type; selecting text switches it to the selection's count ("N words selected"). Counting is CJK-aware (each CJK character counts as a word, Latin runs count by word). Hide it from the status bar's own right-click menu if you don't want it.
- **Resizable Table of Contents** — a chrome-free TOC docks on either side (`birta.tocPosition`), resizes by dragging, hides to a small tab, and switches sides in place. When collapsed, hovering (or focusing) the tab flies the panel out as a floating overlay so you can jump around without reopening it; click the tab to dock it open — the flyout is fully live, tracking the document and reordering from it exactly like the docked panel. Drag TOC items to reorder whole sections, or drag blocks into a section to refile them.
- **Sticky heading** — the heading of the section you're reading stays pinned just under the toolbar as you scroll, carrying its own fold chevron and block handle. Click its title to jump back to the real heading, with the caret placed on the exact character you clicked; a title too long for the column truncates with the full text on hover.
- **Source line numbers** — an optional column of quiet, low-contrast line numbers along the start edge of the window, for the times a rendered document has to be matched against something that speaks in line numbers: a diff, a build error, a review comment, an agent. They are **display only** (nothing to click, and the margin still starts a marquee selection) and off by default — turn them on with `birta.lineNumbers` or the **Toggle Line Numbers** command. The spacing follows the rendered document rather than a fixed ladder, because a source line has no fixed height once rendered: a paragraph that wraps to six rows gets one number and the room it takes, a heading's number sits beside its text, each table row and list item gets its own, and a line that renders nothing (a blank separator, a closing fence, a table's `|---|` row) sits in the whitespace *after* the block it follows — tucked directly above the block it precedes when a tight margin leaves no room for it, rather than dropping out of the sequence. Two deliberate omissions: a code block's interior is left to the code block's own line numbers rather than counted twice, and a line the editor can't place honestly — inside a collapsed section, or in a document whose text no longer matches the saved source — gets no number at all instead of a wrong one. With the setting off nothing is loaded, so launch is unaffected.
- **Live theme following** — the editor always matches your active VS Code color theme, recoloring instantly on theme and OS light/dark switches (Mermaid diagrams included).
- **Keyboard-first** — a Keyboard Shortcuts Help cheatsheet, plus command-palette entries for fonts, checks, and view toggles. UI-level actions — the list and heading chords (⌘⇧7–9, ⌘⌥0–6), find and its navigation, Replace, Insert/Edit Link (⌘K), Delete Block (⌘⇧K), Fold/Unfold (⌘⌥[ / ⌘⌥]), Open Block Menu (⌘.), Go to Symbol, and the Raw Markdown switch — are contributed VS Code keybindings, rebindable in the Keyboard Shortcuts editor. The typing-level grammar keeps a fixed chord set, including formatting (⌘B, ⌘I, ⌘E, ⌘⇧X), undo/redo, block move (⌥↑/↓) and duplicate (⇧⌥↑/↓), block selection (Escape, Shift+↑/↓, ⌘A), expand/shrink selection, and insert paragraph above/below (⌘↩, ⌘⇧↩); those defaults can't be reassigned, but each — undo/redo aside — also has a command-palette entry you can bind an additional chord to.

**Writing assistance**

- **Proofreading (offline)** — spelling, a Harper-backed grammar engine, and style checks (fillers, clichés, wordiness, passive voice, AI-tell vocabulary, em-dash and punctuation, and more) underline issues inline; click one for a popup with a one-click fix, Ignore, or Add to dictionary. A unified **Checks** menu groups them under a master **Proofreading** switch (`birta.proofreading.enabled`), and each check toggles individually. It runs entirely offline, is decoration-only, and loads lazily so it never delays opening a file — a check you've turned off costs nothing.
- **Editor notes are highlighted where they sit** — the markers you leave yourself while drafting (`[TK]`, `[TK: …]`, `TODO:`, `FIXME:`, and anything in `birta.notes.customMarkers`) now carry a quiet chip in the text, so a draft's unresolved bits are visible without opening the review sidebar. One tint for every kind — triage belongs in the Notes tab, not in the prose — and only the marker itself is highlighted, never its line. HTML comments are left alone: they already render distinctly. On by default, off costs nothing, and the switch applies immediately to open editors. Like every other note behavior, a marker inside backticks is source and stays undecorated. Turn it on or off wherever you already are: a **Highlight notes** switch leading the toolbar's Checks menu, a **Highlight** toggle on the review sidebar's Notes tab, the **Highlight Notes** command (palette and slash menu), or `birta.notes.highlightMarkers` — all the same switch, and all four stay in sync across every open editor. In the Checks menu it sits *above* **Proofreading** as its sibling, not inside it: turning proofreading off silences spelling, grammar, and style, but never your own notes, which are content rather than findings.
- **Review sidebar — Links, Notes, and Proofreading tabs** — the table-of-contents drawer is now a review panel: **Contents / Links / Notes / Proofreading**, where a review tab appears only while it has entries (an empty list — or proofreading switched off — shows no tab). **Links** lists every link in the document — inline, autolink, reference, and wikilink — grouped by *destination* (Web / Local files / This document / Email; a wikilink to a file sits under Local files); hovering a row always shows its URL inline beside the title, and both the URL text and an **Open** action follow the link directly from the sidebar — an in-document `#anchor` jumps to its target heading. The **Proofread** tab keeps its full name in the Checks menu. **Notes** lists the editor-note markers you leave for yourself while drafting — `[TK]` and `[TK: …]` placeholders, `TODO:` / `FIXME:`, and HTML comments — each clickable to jump to (a note is document content, so clearing one means editing the document); add your own markers with `birta.notes.customMarkers` (a plain token like `DRAFT` matches only as a whole word). **Proofreading** lists every current spelling, grammar, and style finding with the same **Ignore** (and **Add to dictionary**, for spelling) it offers inline; the Checks menu gains a **Show issues** shortcut that opens straight to it. All three review lists group by type under collapsible headers by default, with a **By type / In order** toggle (remembered via `birta.review.groupByType`) and a full-width **Show more** row capping big groups; jumps from the review lists land with a couple of lines of lead-in context above the target. The **Contents** tab's outline is foldable — H1/H2 headings with sub-headings always show the disclosure arrow, deeper ones on hover (view only; it never folds the document). Inside the sidebar everything is keyboard-navigable: Tab steps between the tab strip, the **By type / In order** row (with the Notes tab's **Highlight** switch), and the list; the arrows move within whichever of those you're on; Enter jumps, folds, or flips; Escape hands focus back to the editor. When the panel is too narrow for its tabs and they collapse into a dropdown, that dropdown is drivable too — Enter opens it on the current tab, the arrows walk it, Escape closes it. *Getting* to the sidebar from the text still needs the mouse: Tab is the editor's own indent key, so no keyboard gesture moves focus out to the panel yet. The tabs share the same docked / flyout drawer, only the tab you're viewing does any work, and the has-entries checks run on idle — never while the document is opening or you're typing.

**Coding-agent integration**

- **Share your file and selection with AI coding agents** — a coding agent (Copilot, Cursor, the Claude/Codex sidebars, and others) normally can't see which file you have open or what you've selected while you're in the WYSIWYG editor, because VS Code hides a custom editor from its active-editor API. Three ways to close that gap, so you stop hand-directing the agent to "look at lines 12–20 of note.md":
  - **A precise clipboard reference, one click away** — select text and the floating selection palette's AI button (a chat bubble with a sparkle) puts a `path.md#L12-L20` reference on your clipboard, ready to paste into any agent's chat (hide it with `birta.floatingToolbar.items.agentReference`). The same **Copy Reference for AI Agent** / **Copy Selection + Reference for AI Agent** commands sit at the top of the editor's right-click menu and in the command palette — the latter quotes exactly what you selected below the reference as a fenced markdown block — real source markdown (headings, list markers, links intact), trimmed to your selection's exact start and end even mid-line — so pasted content reads as quoted material rather than part of your message. Works with every agent.
  - **A Language Model Tool** (`#birtaSelection`) lets Copilot agent mode (and any tool-using agent) pull your current file, caret, and selection on demand — no copy-paste. Requires VS Code 1.95+.
  - **A public extension API** (`getActiveEditorContext()`, returned from the extension's `activate()`) lets any cooperating extension read the same live file + selection.

### Fixed

- **Turning a list item into a paragraph now actually leaves the list** — un-bulleting an item (Backspace at its start, Shift+Tab, the toolbar's Lists toggle) looked right on screen, but the saved file glued the new paragraph directly under the item above it, with no blank line between. Markdown reads a line like that as more of the previous bullet's text, so reopening the file — or a later edit that re-read it — showed the paragraph swallowed back into the list: fused onto the bullet above (`- two three`) when you lifted an item from the middle, or back inside the list when you lifted the last one. The blank line the file needs is now written, so what you saved is what you get back. This covers bullet, numbered, and task lists, at any position in the list, including sublists indented with four spaces or tabs. Spacing you wrote yourself is still never rewritten — only a blank line the document's meaning depends on is added.
- **Dropping several images at once now inserts all of them** — selecting three images and dragging them in together inserted one and discarded the other two, with no message: the drop looked like it had worked. All of them now land, stacked in the order you dragged them, as a single edit one undo takes back; the pill that marks the spot says how many are saving. If one of them can't be saved, the rest still land and the message says how many didn't. Pasting several copied image files at once behaves the same way.
- **The inline calculator no longer gives up on a preceding parenthesis** — `here's the formula (3+7=` offered nothing, because an opening parenthesis you haven't closed yet was swallowed into the expression, which then couldn't parse. An unmatched *leading* paren is now read as the prose punctuation it is, so the answer arrives and the paren stays exactly where you typed it (`(3+7= 10)`). The same fix covers the `=>` form. Everything that was refused before still is: an unmatched paren *inside* the expression (`2*(3+7=`) means you're mid-formula, a run glued to a letter (`f(3+7=`) is a function call, and a trailing unmatched `)` still reads as the tail of something larger — a wrong answer is worse than none.
- **The inline calculator's `=` now works inside a code span** — typing `` `3+7=` `` offered nothing, because the suggestion machinery refused inline code outright (right for link autocompletion, wrong for arithmetic — a backticked expression is exactly where many people put it). The answer is offered as usual and lands inside the span. The richer `=>` form deliberately still declines there: its answers are kept alive against definitions elsewhere in the document, and that maintenance can't see inside a code span — so an answer accepted there would be one the editor could neither update nor flag when its premise changed. Also unchanged: a fenced code block never computes, and a `name = value` line in backticks is still source, not a variable definition.
- **The table of contents no longer slides in when a document opens** — the panel's load-time reveal is meant to snap into place rather than animate, but which of two commits actually opened it depended on whether the editor finished mounting inside a single frame. When the mount won that race, the panel faded and slid in on open — drawing attention to itself exactly when it shouldn't. Both commits are now covered, in whichever order they arrive; a show/hide you invoke yourself still animates as before.
- **Clicking a rendered diagram or formula no longer leaves an invisible caret behind** — the caret stayed where it had been in your text, so the next Enter split a paragraph somewhere else in the document with nothing on screen to show it had happened. The editor now goes inert when you click a rendered preview, until you click back into text. Clicking the chrome *around* a preview — the language pill, the width and word-wrap buttons, the fullscreen control — can still leave the caret live; that is being handled separately.
- **Editing an image's path or caption from its toolbar now shows a caret, and shows what you have selected** — while the image stayed selected, its fields drew no text cursor, and selecting text in them painted no highlight at all, so a select-all looked identical to having selected nothing.
- **Typing above or below a table (or code block) no longer goes into it** — a block that starts the document, ends it, or sits directly against another one had no caret position beside it, so arrowing or clicking toward that gap put the caret *inside* the neighbouring block instead. The next thing you typed then landed in a table cell or in a line of code, at a caret you believed was in the gap: above a leading table, below a trailing one, between two adjacent tables, or above a document that opens with a fenced code block. Those positions now exist and show a caret, and clicking the empty space above the content reaches the first of them, as clicking below the content already did. The ⌘↵ / ⌘⇧↵ shortcuts for inserting a paragraph after/before a block are unchanged. One related case is *not* fixed: pressing ↓ onto a horizontal rule still selects the rule, so a keystroke replaces it — the position beside an `hr` is not one of these gaps, and it is being handled separately.
- **View state now survives switching to the raw editor and back** — folds, scroll position, and the metadata (frontmatter) panel's Hide/Show choice were silently reset every time you round-tripped through "Edit Raw Markdown", because that switch closes and recreates the editor's webview. The editor now keeps each document's view state for the session and restores it when the file reopens in Birta.

- **A file with unsaved changes is never taken over by the rendered editor** — with a `.md` file open in Birta and edits you hadn't saved, anything that also opened it in the raw editor (clicking a search result for that file, following a link to it) made Birta close that raw tab to render it — and closing an unsaved file is what makes VS Code ask "Do you want to save…?", with the wrong answer discarding the edit. Birta now leaves a raw tab with unsaved changes alone: no prompt, no risk, at the cost of that tab staying open in raw Markdown until you save. Freshly opened files are unaffected, and switching modes yourself with ⇧⌘M still works exactly as before.

- **Clicking a search result now lands on the match** — a hit in VS Code's search (⇧⌘F) opened the file in Birta and then sat at the top of it: no selection, no scroll, leaving you to hunt for the line yourself. The match is now selected and revealed — centered, with no scrolling animation — exactly as it is in the raw editor, whether or not the file was already open. An arriving jump also takes precedence over the editor's remembered scroll position, which could previously snap you back to where you last left the file a moment after landing (that applies to the cursor carried in from the raw editor too). Any other navigation VS Code aims at a Markdown file arrives the same way: a problems-panel entry, a `file.md#L120` link, or `code -g file.md:120`. Opening a file normally is unaffected — it still returns to where you left it.

- **Find results no longer go stale after you edit** — the find bar computed its matches once per search, so editing the document left it lying: delete one of 15 matches and it kept showing 15, and — worse — Find Next jumped to where matches *used* to be, landing offset by exactly what you'd inserted or deleted; Replace All could even rewrite the wrong characters. Anything that acts on a match (Find Next/Previous, ⌘D occurrence cycling, Replace, Replace All) now re-searches the live document first, so it can never act on stale positions, and the count and highlights refresh on their own shortly after you pause editing.
- **A file written with Windows line endings no longer comes back with mixed ones** — in a `.md` file saved with CRLF endings, typing a single character rewrote the paragraph you edited (and the blank lines around it) with Unix LF endings while the rest of the file kept its CRLF, leaving a file that was consistently neither. Every line you don't touch now keeps the exact ending it was written with, an edited line keeps its own, and a line you add takes the ending the rest of the file uses. The same fix restores the editor's other formatting guarantees on these files: because a stray `\r` also defeated the checks that recognize a divider or an underlined heading, a CRLF file's `- - -` divider was rewritten to `---` on an unrelated edit where an otherwise identical LF file's was left alone. Both are now treated the same.

- **Editing a tab-indented outline block no longer detaches the blocks nested under it** — in a file whose nesting is written with tabs (a Logseq graph, or any hand-written outline), typing into a block that had children rewrote *that* line with space indentation while its untouched children kept their tabs. Because a tab is a wider indent than the two spaces that replaced it, the children ended up indented too far relative to their parent and stopped being list items at all — a child could reopen as literal text (`\- child`) inside the block above it, one keystroke after touching an unrelated word. An edited line now keeps the exact indentation it was written with, so the outline around it is unchanged. That now extends to outlines that **mix** indent units — a parent indented with a tab and its child with a tab plus spaces, the shape a hand-edited outline drifts into — where the edited line used to fall out of the tree and become a sibling of its own parent. Genuinely indenting or outdenting a block still saves as the real change it is. One limit worth knowing, still open: when *two neighbouring* lines are written with the same unusual indent, editing one of them can still shift it. (Moving a block was a second such limit and is covered separately below.)

- **Moving a block in a tab-indented outline no longer re-nests the file** — dragging a block, or moving it with Alt+↑/↓, in a file whose nesting is written with tabs (a Logseq graph, or any hand-written outline) saved the moved line with the editor's own two-space indentation while every line you didn't touch kept its tabs. A tab is a wider indent than two spaces, so on reopening the file the moved block sat at a different depth than the one you left it at: a sibling became a child, a nested list appeared that you never made, and in a deep outline a block could stop being a list item at all and come back as literal text inside its neighbour. This did **not** need an unusual file — a plain tab outline, the ordinary Logseq or Obsidian shape, was enough, and it applied to a fifth of the moves possible on a realistic page. A moved block is now written with the indentation the file itself uses at that depth, so the outline you see is the outline that is saved; an item's continuation lines and any code fence inside it move with it, keeping their contents exactly. Moving a block whose content is a *heading* — the one case left open when that fix landed — is covered too; see the entry below.

- **A bullet whose content is a heading or a quote no longer dissolves the list around it** — when a list item's content is something other than a plain paragraph — a heading (`- # Project Atlas`, the ordinary Logseq shape), a quote (`- > note to self`), a code fence, a table — the editor saved it as an *empty* bullet with the content indented underneath. That shape does not mean what it looks like: on reopening, the empty bullet was read as an *underline* for the line above it, so the block above turned into a heading and the nesting under it was gone; in a tab-indented file the content fell out of the bullet entirely and came back as literal text in a code block, `#` and `>` and all. Both moving such an item (drag or Alt+↑/↓) and typing inside one could put that shape on disk. The item is now written with its content on the bullet line, exactly as you wrote it, so the file you reopen is the outline you left. On the realistic Logseq page this was measured against, 10 of the 247 moves you could make were still corrupting the file after the previous indentation fix; none are now. Three shapes are deliberately left as they were: an item whose content is an empty sublist, a blank line you wrote inside an item — both already correct — and an item whose content is a horizontal rule, which is **not** yet correct when it is nested under another bullet (`- normal` above `  - ***` still loses the nesting on reopen). That last one is a pre-existing gap this change does not close, because both available spellings collide with something: bringing the rule up to the bullet line can make the whole line read as one horizontal rule instead.

- **Editing one table cell no longer empties a line break in another cell of the same row** — a table row is a single line, so typing in any cell re-wrote the whole row on save. A cell containing only a line break (`<br />`) came back empty, and `<br/>` / `<br>` spellings elsewhere in that row were rewritten — content lost from cells the cursor never visited. Every cell you didn't edit now keeps its own bytes.
- **Your list markers and numbering are no longer rewritten when you edit a neighboring item** — a list written with `+` or `*` bullets came back with `-`, a `1)` `2)` `3)` list came back as `1.` `2.` `3.`, and a list numbered `1.` `1.` `1.` — the style people use precisely because it survives reordering — was renumbered `1.` `2.` `3.`. Nothing had to be edited *in* those lines: one keystroke anywhere in the list rewrote the marker on every other item, including items you never touched. A list's bullet character, its `.`-or-`)` delimiter, and whether it counts up or repeats one number are now read from your file and written back as you wrote them. Lists you create in the editor are unchanged (`-` bullets, counting up), and a list that Markdown requires to differ from the one directly above it still does — that split is real syntax, not a rewrite.

- **A link in angle brackets no longer grows a backslash every time you save** — a URL ending in a backslash, written `<https://example.com/a\>` or picked up from bare text, doubled its backslashes on each open-and-save cycle: one became two, two became four, four became eight, without limit. Backslashes carry no special meaning inside a bracketed link, so nothing ever undid the escaping the previous save added. Saving is now stable: the link keeps exactly the backslashes you wrote. (A save with no edits was never affected — the growth only started once the line had been touched.)
- **Path suggestions no longer fight an IME** — typing a path inside inline code while composing with a Chinese, Japanese, or Korean input method could lose keystrokes: whenever the suggestion dropdown was open it took Return and the arrow keys out of the whole editor, so choosing a candidate from the IME's own window either did nothing or picked a file instead. Composition keys now pass straight through to the input method, in every path field.

- **Suggestion dropdowns near the bottom of the window stay on screen** — the path and image-path suggestion lists always dropped downward, so a field low in the window opened its list off the bottom edge where it couldn't be read or clicked. They now flip above the field when there isn't room below, the way the link and slash menus already did.

- **Only one suggestion row highlights at a time** — in the image path list, arrowing down to a row while the pointer rested on another painted both as selected, so it was ambiguous which one Return would take. The keyboard highlight is now the only one, and the image list picks up the same suggest-widget styling as the rest of the editor's dropdowns.

- **Typing inside a `~~~` code fence no longer swallows the rest of the file** — when a fence sat just after a line the editor rewrites on save (say a paragraph containing a literal `*`), a single keystroke inside the fence could save its opening line as ``` ``` ``` while leaving the closing `~~~` untouched. The mismatched pair meant everything below the fence reopened *as code*, silently. Fences now keep the marker style they were written with, whatever is around them.

- **A file you just created is offered as a link target right away** — link autocomplete and the frontmatter value suggestions worked from a workspace scan refreshed on a timer, so a newly added file could take up to ten seconds to become suggestible and a deleted one kept being offered until the timer lapsed. Both now refresh the moment a file is created, deleted, or renamed.

- **Adding a heading that repeats an existing one no longer silently hijacks its links** — in-note links target a heading by its text-derived slug, and two headings with the same text are told apart by a `-1` suffix in document order. Introducing a *new* heading above an identical one therefore renames the older heading's anchor out from under it, and existing `[…](#foo)` links quietly began jumping to the newcomer instead of the section they were written for — with nothing on screen to show it had happened. Those links now follow the heading they were pointing at. This covers every way a heading appears: pasting one in, pasting over a selection, and promoting a paragraph with `# ` or the gutter control. Duplicating a section is handled the way you'd want too — the copy's own links keep pointing inside the copy.

- **Editing a Mermaid diagram no longer corrupts its re-render** — toggling a ` ```mermaid ` block to code, editing the definition, and toggling back (or editing in the fullscreen view) often came back mangled: node text clipped, boxes too small or too large, the whole layout mis-sized — whenever the diagram wasn't resting at exactly 100% zoom, with reopening the file the only cure. Rendering now measures the diagram on a clean off-screen surface instead of inside the zoomed preview, so every re-render lays out exactly like the first.
- **Mermaid diagrams now follow theme changes** — with `birta.mermaid.theme: auto`, switching VS Code between light and dark (or changing the setting itself) left already-rendered diagrams in their old palette until their text next changed; they now repaint in place. A re-render requested while a slow render is still in flight is also no longer silently dropped — the newest definition always wins.
- **Switching a preview block between diagram / formula / calculation languages now switches the preview** — changing, say, a ` ```math ` block's language to `mermaid` from the picker left the stale formula on screen while the diagram rendered into a hidden pane; the right preview now appears (and flipping to a previewable language while the block is empty drops to code mode so it stays editable).
- **The editor never rewrites a list's tight/loose spacing** — a keystroke near a nested list used to insert blank lines between every item on save, and edits inside a deliberately loose list silently deleted its authored blank lines. A list's spacing is the author's call (it also changes rendered output — loose items get paragraph spacing downstream), so no edit changes it anymore: the editor only ever *adds* a blank line Markdown genuinely requires — a second paragraph inside an item, or the one that separates a list from a paragraph you just un-bulleted out of it (see Fixed) — new items inherit their list's spacing, and lists created in the editor start tight. This now holds per *gap*, not just per list: a list with one stray blank line in the middle of it keeps that blank line exactly where it was and stays tight everywhere else, where previously editing anywhere in such a list spread blank lines between every item on save. Deliberate cleanup is the new **Tighten List** action (see Added).
- **Typing right after a link no longer extends the link** — inserting a link (⌘K, a section-link pick, pasting a URL, or typing `[text](url)`) leaves the caret at the link's end, and the next characters used to silently join the link's text. They are now plain text; to change a link's own text, use the link editor.
- **Typing `60*60*1000` no longer italicizes the middle number** — a `*` pair that reads as multiplication (flanked by a digit, `)`, or a word character with numeric content between the stars) stays literal text instead of becoming emphasis, so inline arithmetic survives as typed; the literal stars are escaped on save (`\*`) and round-trip. Prose italics are untouched — `a *word*` and even intraword `great*idea*` still emphasize. (A file authored elsewhere with bare `60*60*1000` still parses as CommonMark emphasis on open; write `60 * 60` or use a ` ```calc ` block for formula-heavy text.)

- **A just-inserted diagram / math / calc block stays editable** — inserting an empty ` ```mermaid `, ` ```math `, or ` ```calc ` block used to drop straight into its rendered preview, which hides the source, so there was nowhere to type; empty previewable blocks now start in code mode (a non-empty one still opens in preview, as before).

- **Converting a list now converts the whole tree, everywhere** — switching a list between bullet / ordered / task used to change only the outermost layer from the block menu (a bullet list with nested sub-items came back "ordered" on top with bullet children), and the toolbar's Lists menu and the `/` slash menu couldn't convert an existing list at all (picking another flavor with the caret in a list either did nothing useful or tried to nest a new list). All three surfaces now run one converter: pick a flavor anywhere in a list and the entire tree — the list, its items, and every nested list at every depth — becomes that flavor in a single undo step. Converting *to* a task list preserves boxes already ticked in nested task items; converting away clears them. Picking the flavor a list already has still toggles the caret's line out of the list, exactly as before, and using the buttons outside a list still wraps the selection.

- **Deleting what separates two lists now leaves one list, not two** — removing the paragraph between two same-kind lists (or moving a list next to another, or converting the block between them into a matching list) used to leave two adjacent lists that read as separate blocks: a full block gap between them where items have a small one, two gutter handles, and — worse — a save made the split *permanent* by switching the second list's bullet marker (`-` → `*`), since that's the only way Markdown can express adjacent lists. Adjacency your own edit creates now merges into one list automatically, in the same undo step (one Cmd+Z restores the separator and the split together). A split the file *already* carries — a deliberate `-`/`*` marker change — is the author's syntax and is never merged silently; merging those is offered instead (see Added).

- **A document ending in an unclosed code fence is no longer "closed" by saving** — a file whose last construct is an unterminated ` ``` ` fence (a snippet cut off mid-paste, a template, a deliberately open example) gained a synthetic closing fence on every save, even a save with zero edits. The fidelity layer could pin existing bytes against rewrites but had no way to veto a line the round trip *adds*; it now suppresses serializer-synthesized lines the same way, so the file keeps exactly the fence you wrote — at the end of a document or auto-closed inside a blockquote alike. Editing the lines around the open fence still adopts the canonical closed form, matching how every other unreproducible construct behaves.
- **A save after a failed editor rebuild can no longer write the previous content back over the file** — if rebuilding the editor for an external file change failed partway (for instance the syntax-highlighting chunk failing to load for a document with code blocks), the editor showed blank — but a Cmd+S in that state answered the save with the *previous* document's bytes, quietly reverting the on-disk file. A failed rebuild now leaves the save pipeline inert: a save writes the document's own current bytes, and the editor recovers fully on the next successful open.
- **Moving a collapsed section no longer buries the destination's content inside its fold** — dropping a collapsed heading somewhere nothing out-ranks it (say, a collapsed `###` section landing where the next heading is `####` or none at all) silently swallowed every following block into the collapsed fold, with no visual clue the content still existed. If the fold would hide anything at the destination it didn't hide before, it now opens instead, keeping everything visible; a move where the fold's content is unchanged still travels collapsed, exactly as before.
- **A save with no edits can no longer rewrite a file that mixes a tab-indented code block with a divider** — if an indented code line's content coincided with a `***`/`---` divider elsewhere in the document (a `\t***` code line plus a real `***` rule), the fidelity layer mistook one for the other, gave up entirely, and the next save — even with nothing edited — converted the code block to a fence and reflowed constructs the editor can't reproduce byte-for-byte. Lines are now compared with their construct context (code, fence content, prose), so lookalike bytes in different constructs can never be confused.
- **Whitespace edits inside a code fence now save** — swapping a tab for spaces (or the reverse) at the start of a line inside a top-level code fence — a Makefile recipe, a YAML snippet — read as "no change" and was silently reverted on save. Fence content is now compared byte-for-byte. (Inside a fence nested in a tab-indented outline, leading indentation still compares by depth — that's what keeps Logseq files from churning.)
- **Moving a raw `:::` line into a directive no longer merges it into the paragraph above** — dropping unpaired `:::` fence prose at the tail of a `:::tip`-style directive saved fine but reopened with the line glued onto the preceding paragraph, because the merge dropped the blank line the serializer had deliberately emitted between them. The same rule protects a divider moved directly under a paragraph (gluing those turns the paragraph into a heading).
- **A setext (underlined) heading moved next to a dash-style divider now keeps its underline** — the remaining case of the underline "repair" fixed for `***` dividers: a `- - -` divider and a moved `-----` underline could still trade bytes, dissolving the heading into a paragraph and a rule.
- **Delete Block (⌘⇧K) with the caret in a table cell no longer deletes the whole table** — from a plain caret inside a cell the command now does nothing, matching Join Lines' never-destructive rule; deleting a table stays deliberate (select the whole table via its handle, the block menu, or a block/marquee selection).
- **Cmd+S now always saves what you just typed** — a save could silently do nothing and leave your latest keystrokes unwritten. The editor took about 200ms to register an edit with VS Code, and a save inside that window found nothing to write; typing *continuously* never registered at all, so saving mid-flow without pausing could write nothing no matter how long you'd been typing. The same delay bounded how much recent work VS Code's crash backup held. An edit now registers within a frame, so Cmd+S catches it however fast you get there.
- **The outline now updates the instant the document changes** — the table of contents refreshed on the *save* cadence rather than on edits, so how fast it caught up depended on your recent typing: near-instant after a pause, several hundred milliseconds mid-burst, and up to two seconds during continuous typing. It now tracks the document directly and reflects an edit on the next frame, whatever else you're doing.
- **Changing a heading's level no longer buries the content below it in a collapsed section** — if a folded section sat above, retyping a heading to a deeper level (or turning it into a paragraph) could pull that heading and its body inside the fold, where they were hidden: one click, no warning, and blocks you never touched were gone from view until you unfolded the section above. A section's extent follows the heading levels around it, so the fold now opens whenever an edit would grow it over content you could see — the same rule that keeps a dropped block visible.
- **A block dropped at the end of a collapsed section no longer disappears** — dragging a block to the boundary just below a folded heading (dragging it to the bottom of the document was the easiest way to hit this) dropped it *inside* that collapsed section, where it was hidden: the block vanished with no trace, reading as if the drag had deleted it. It was still in the file, but the only way to find it was to unfold the section. The fold now opens to show the block where you dropped it.
- **Pasting into a collapsed list item's first line no longer hides part of your own text** — pasting multi-paragraph content mid-way through the visible first line of a collapsed list item silently tore that line in half: everything after the paste point, plus part of the pasted content, ended up hidden inside the fold, so the item read as just the head of its first line with no clue the rest existed. A fold now opens whenever an edit would grow it backward over content you could see — completing the rule that already guarded a fold's other end. Content that lands programmatically at the first hidden position under a collapsed heading is revealed the same way, while ordinary edits in a collapsed item's visible line — and syncs that add content wholly inside a collapsed section — still leave the fold alone.
- **"Move Up" on a block nested in a list item no longer looks available when it isn't** — the first block under a list item's own line (an indented quote, code block, callout, table, or heading) offered a live "Move Up" row that did nothing when clicked. It can't move up: a list item has to start with its own text, so nothing else can take that first line. The row is now disabled, like every other move with nowhere to go. Moving such a block *down* past its siblings is unaffected.
- **Editing one block in a Logseq file no longer rewrites its neighbors** — Logseq graphs indent their whole block tree with tabs and carry org-style tokens (`[#A]` priorities, `CLOCK:` timestamps, `[3/7]` progress). Editing one nested block used to silently rewrite the surrounding run — tabs collapsed to spaces and `[#A]` became the meaningless literal `\[#A]` on lines never touched, scaling to most of a deeply nested page. Untouched lines now keep their bytes exactly, and the edited line itself keeps its org tokens unescaped (a bracket that matches a reference definition elsewhere in the file keeps its escape — unescaping it would create a link).
- **Moving a setext (underlined) heading no longer dissolves it near a `***` divider** — the save could "repair" the heading's `-----` underline into the divider's `***` bytes, splitting the heading into a paragraph and a rule.
- **Nested headings' gutter badges now sit on their text line** — every heading inside a blockquote, callout, or directive drew its H1–H6 gutter badge about 8px below the line it belongs to (more at higher zoom), because the offset compensated a padding at the wrong size. All six levels now align at every content scale.
- **Screen readers no longer hear two selected items in the block menu** — on a callout set to "Collapsed by default", both that row and the "Callout" block type announced as selected, though the menu allows only one selection. The fold toggle now announces as a checked item, which is what it is; the block type keeps the selection.
- **Heading grabber handles now center on their text line** — every top-level heading's H1–H6 badge and fold chevron sat about a third of a line below the first line of text (the same wrong-size padding compensation already fixed for nested headings). They now center on the line at every level and content scale.
- **The pinned heading's tooltips are no longer hidden behind the toolbar** — hovering a truncated pinned-heading title (or its fold chevron) drew the tooltip on top of, and partly behind, the fixed toolbar. A tooltip now drops below its control whenever the toolbar leaves no room above.
- **The ToC flyout now opens at your place in the document** — hovering the collapsed tab used to show the outline scrolled to the top, so in a long document the highlighted current section sat out of view below the fold; the flyout now opens with the active heading centered in the list.
- **A block menu opened near the toolbar can no longer overflow the window** — when a block's menu anchor sat scrolled under the toolbar, the menu was pushed down below the bar without shrinking and its tail ran off the bottom of the window; it now sizes to the space actually available and scrolls inside itself.
- **Customize Toolbar's two drop areas no longer overlap** — the left and right placement zones' drop-target outlines ran into each other in customize mode; the toolbar's two halves now keep a small permanent gap (also visible, subtly, in normal use), so the outlines stay distinct.
- **The table of contents no longer starts its first row under the panel buttons** — docked, the side-switch and hide buttons floated on top of the first outline row. The list now starts below them and keeps clear of the window's bottom edge, and the hover flyout gained breathing room above the first and below the last row inside its card.
- **The ToC hover flyout now shrinks to fit a short outline** — the floating flyout inherited the docked drawer's full height, so a document with only a handful of headings showed the list followed by a tall stretch of empty card. The flyout now sizes to its contents (still capped, scrolling only once the outline is long), so the card ends just below the last heading.
- **Showing or hiding the table of contents now sticks** — once you toggle the outline panel open or closed, that choice used to reset whenever the editor was recreated from scratch (reopening the file or reloading the window), falling back to the auto-open-by-heading-count default. The choice is now saved to a new `birta.tocVisibility` setting (`auto` — the default, decide by heading count per `birta.tocAutoHideThreshold` — / `shown` / `hidden`); toggling the panel writes it, and it applies to every file and window until you change it. Changing it (by toggling, or by editing settings) updates every open editor at once, so multiple tabs no longer drift out of sync.
- **Content no longer risks starting under the toolbar with a large UI font** — the editor's top clearance was a fixed 56px while the toolbar's height grows with the UI font, leaving almost no gap (or none) at larger font sizes. The clearance now tracks the toolbar's real height, and hiding the toolbar reclaims its space.
- **Switching between rich text and Raw Markdown now keeps your cursor — and your selection** — the switch moved the *view* but never the caret, so it landed wherever the other editor happened to leave it: arriving in rich text, the page scrolled to your line while the cursor stayed at the top of the document, and the first thing you typed after the switch went in at the very beginning of the file. Going the other way, the raw editor opened at whatever line happened to be in the middle of the screen rather than the one you were editing. Cmd+Shift+M (and the toolbar's Edit Raw Markdown, and the right-click entry) now carries the cursor itself, column included, in both directions — so you can switch mid-sentence and keep typing where you left off. If you had text selected, the whole selection survives the switch too, drag direction included — even when you've scrolled it off screen, and even when it's a *block* selection (Escape / Shift+↑↓, the marquee, or select-all), which arrives in the raw editor as those blocks' whole source lines, a fenced code block's closing ` ``` ` included. The column holds even inside formatted text — `**bold**`, links, inline code — by aligning what you see to the characters the source actually has; only where the two genuinely can't be aligned (an image, math) does it fall back to the start of the line. Hard-wrapped paragraphs (one paragraph over several source lines) now map line-by-line too: the cursor or selection lands on the exact wrapped line it was on, where it previously collapsed to the paragraph's first line. Tables map row-by-row: a cursor or selection in a cell switches to that row's `| … |` source line — column placed inside the right cell's text — and back, where it previously could land hundreds of lines from the table entirely. Callouts, container directives (nested included), and Notion asides now map their bodies to the right lines too — their `> [!NOTE]` / `:::name` / `<aside>` marker lines used to shift every line inside by one or more — and selecting text in a calculation block's rendered ledger carries that row's exact source line and column, where it previously switched to wherever the caret last was. A selection in a callout's or directive's title (folded or not) carries onto its marker line with exact columns too. The raw editor also scrolls your arriving cursor to the center of the view — matching what the rich-text side does — instead of parking it at the viewport edge, and the rich-text editor now opens already scrolled to your spot instead of painting the top of the document and visibly jumping down a moment later. When you've scrolled away from a bare cursor (no selection), the switch still takes you to what you're looking at instead, since that's the place you actually asked for. Jumping to a search result in the rich-text editor now places the cursor on the line too, instead of only scrolling to it.
- **The Raw Markdown keybinding now switches the pane you're focused in** — with two editors split side by side, Cmd+Shift+M (Ctrl+Shift+M) always switched the leftmost pane no matter which one had focus; the toolbar's Edit Raw Markdown button was unaffected. The shortcut now targets the focused editor, matching the button.
- **Jumping to a line now lands on the block you asked for** — two separate causes made the two editors disagree about what a line number means, and both showed up as arriving *near* your target instead of on it. **Frontmatter**: the line map counted the YAML metadata block that the rich-text view doesn't show, so every line the editors exchanged was off by the height of that block, and the gap grew with the size of your metadata. **Loose lists**: a list with blank lines between its items is several blocks in the file but one in the editor, so from that list onward every line resolved one block early — and each further loose list added another block of drift. Line numbers are now translated across the metadata boundary, and a line is checked against the text of the block it claims to be in before the editor acts on it, so a global-search hit or a switch from Raw Markdown arrives in the right place in both cases.
- **The Edit Rendered Markdown shortcut and button now work on a file another extension has claimed** — a recent VS Code ships a built-in extension that assigns its own language id to files matching certain names and extensions (for instance any file named exactly `SKILL.md`, or one ending in `.instructions.md` or `.agent.md`), even though the file is still ordinary Markdown on disk. Cmd+Shift+M and its editor-title button were gated on VS Code's own `markdown` language id, so on one of these files the shortcut silently did nothing — it worked in every other window, on every other `.md` file, which made it look like a one-off glitch rather than a real gap. Both now also match by file extension (`.md` / `.markdown`), independent of whichever language id currently owns the file.

### Changed

- **Calc answers now survive being pasted into another calculator — and where no convention wins, Birta declines to answer** — an equation lives in a plain `.md` file, so it gets handed to some other calculator sooner or later and must answer the same there. Three notations changed to follow the overwhelming majority. **`%` is now floored modulo**, carrying the sign of the *divisor*: `-10 % 3` is `2`, as in `MOD` in Excel and Sheets, Python, Ruby and Wolfram — it was JavaScript's truncating remainder (`-1`), which only the C-family languages agree with. **`round` now sends halves away from zero**, so `round(-2.5)` is `-3` and `round(-x)` is always `-round(x)`; JavaScript's own rounding broke that symmetry. And **a bare `log(…)` no longer computes at all**: it means base 10 in spreadsheets, Desmos and every pocket-calculator LOG key, and the natural log in Python, R, Mathematica and JavaScript, so either answer would be silently wrong for half the people who read the file, with nothing in the number to reveal it. Instead, `log(100) =>` offers *both* readings side by side with the value each gives, and picking one rewrites the equation itself to `log10(100)` or `ln(100)`, so the meaning travels with the note; in a ` ```calc ` block the line takes the quiet error dash and its tooltip says what to write instead. `log10`, `log2`, and `ln` were always available and are unchanged, as are the conventions that were already right and are now written down: trig is in radians, `^` is right-associative, and `-2 ^ 2` is `-4`. **Answers you already accepted are left exactly as they are** — a `log(100) => 2`, or a `%` result computed the old way, is your text now, so nothing is rewritten, withdrawn, or flagged behind your back; re-accept the equation if you want the new reading.
- **Selecting blocks no longer stalls a long document** — selecting a run of blocks, an image, a horizontal rule, or a range of table cells made the editor restyle the entire document, about 170 ms on a 300 KB file and again when the selection was released. It also hit every arrow key that lands the caret in the gap beside a table or code block. It is now under 5 ms, and the total time the editor spends blocked across a burst of selections dropped by about 75%. Nothing looks different: the block tint, the selection highlight, and every caret are unchanged.
- **Typing in a long document no longer stutters** — on a very large file (300 KB, several thousand blocks) each keystroke took around 45 ms of blocked main thread, which reads as the caret lagging behind your fingers; it is now around 6 ms, and the total time the editor spends blocked during a typing burst dropped by roughly 85%. A 96 KB file went from ~7 ms to ~2 ms per keystroke — low enough that it no longer registers a single long frame across a whole typing burst — and a link-heavy document from ~4 ms to ~2.6 ms. **Moving the caret got faster too**: on that 300 KB file every arrow key, click, and selection change was costing ~5.5 ms of the same blocked main thread, now ~3.4 ms. **Editing code got the largest speed-up of all** — typing inside a fenced code block in that file cost ~38 ms per keystroke, because every keystroke re-highlighted every code block in the whole document; only the block you are editing is re-highlighted now, and it costs ~9 ms. Pressing Enter (and other edits that change document structure) went from ~33 ms to ~20 ms. Opening a file is unaffected — the handles for what's on screen are worked out after the editor has painted, never before it. Three separate causes, all fixed: the per-block gutter chrome maintained every block's handle for the whole document on every keystroke, including the thousands of blocks scrolled far out of sight (handles are now built for what's on screen, with a wide margin, and appear as you scroll); a table-alignment rule inherited from the Markdown editing framework re-walked the *entire* document on every keystroke, even in documents containing no tables at all; and the syntax-highlighting plugin walked the whole document twice on *every* transaction — including ones that only moved the caret, which is why plain cursor movement was paying for it. Nothing about the document is affected by any of them: block positions and page height are unchanged, folded sections stay folded wherever they sit, table column alignment still follows its header, and syntax highlighting is byte-for-byte what it was before.
- **Opening a document is faster, whether or not you ever use Find** — a large file (300 KB) now opens about 10% quicker, and a medium one about 6%. The find bar's match highlighting was defined in the stylesheet loaded at startup, and the browser resolves a style for every registered highlight name while resolving *every* element's style — so every document was paying for search highlighting on open, including documents where Find was never opened. Those styles are now installed the first time something is actually highlighted. Nothing about Find changes: matches, the current match, and the search scope look exactly as before, from the first search onward.
- **Find in Selection now shades the range it is searching** — with the toggle on, the search is confined to the range you had selected when you turned it on, but nothing marked that range: the only signal was the toggle's pressed state, and once focus moved into the find input the selection highlight could stop rendering, so matches elsewhere in the document read as having vanished for no reason. The scoped range is now tinted (using VS Code's own find-range color, so your theme decides how it reads), with matches inside it still painting on top.
- **"Select All Occurrences" is now "Change All Occurrences", and answers ⌘F2** — the old title borrowed VS Code's ⇧⌘L verb, which puts a cursor at every match; Birta is a single-selection editor and cannot do that, so the name promised something it never delivered. What the command actually does — seed the search from your selection and open the find bar focused on Replace, ready to change every occurrence — is VS Code's **Change All Occurrences** (⌘F2), so it now carries that name and that shortcut. ⇧⌘L keeps working as a second binding.
- **`birta.calc.enabled` now applies to open editors immediately** — flipping the inline-calculator switch in settings reaches every open editor live (suggestions, answer maintenance, and the stale/broken cues all follow), instead of waiting for the file to be reopened.
- **Backspace at the start of a nested list item now joins it onto the previous line** — the item break is deleted like a text editor joining lines: the item's text lands at the end of the line above and its sub-items follow one level up, instead of the old outdent-one-level-per-press that dragged whole subtrees through every nesting level. Cmd+Backspace (delete to line start) on an already-empty item now deletes the item and returns the caret to the previous line instead of doing nothing. Top-level items are unchanged: Backspace at their start still removes the bullet (the item becomes a paragraph). The join only ever targets a paragraph — an item sitting below a code block outdents instead, so a keystroke can never pour prose into the code.
- **The editor chrome now shares one visual system** — buttons, menus, popups, and panels across the toolbar, find bar, table of contents, link editor, image and selection toolbars, code-block headers, and the metadata panel draw from a single set of corner radii, text sizes, and hover behaviors instead of near-identical per-surface values; menu rows and their group headings (block menu, slash menu, toolbar dropdowns, pickers, autocomplete lists) share one row anatomy and highlight behavior as well. Customize Toolbar joins the system: its **Done** button now matches the standard filled-button style (it was the app's only fully-rounded pill), and the **Hidden** tray wears a faint diagonal-stripe pattern so "off the bar" reads differently from the two placement areas at a glance. Most differences were a pixel of drift and won't be noticed; the visible normalizations are cohesive corners on floating menus and panels (one radius instead of three) and consistent press/hover feedback on small icon buttons.
- **Floating menus and panels cast a much lighter shadow** — roughly half the ink of before, so a menu, popup, panel, toolbar, or tooltip reads as lifted off the page instead of ringed by a dark halo. Every floating surface shares the one shadow, and it stays a quiet dark lift on every theme: the outline fly-out, its tab-overflow menu, the Keyboard Shortcuts card, and the link popup previously used the theme's own widget-shadow, which read differently from every other menu and, on some dark themes, inverted to a light cast that looked like a glow. The image-insert dialog and the image lightbox — the two things that float over the whole editor rather than next to something — keep a wider, softer version of the same shadow. A diagram opened fullscreen is crisper too: the shadow now sits under its white canvas, where it belongs, instead of tracing a grey halo around every node, edge, and label in the diagram itself.
- **Copying from the editor now copies Markdown** — Cmd+C, cut, dragging text out of the editor, and the native Copy menu put the selection's Markdown source on the clipboard's plain-text flavor, so pasting into any plain-text target (a chat box, a code editor, another markdown file) keeps the syntax instead of flattening it to bare prose. A selection *inside* one block stays proportionate: copying a few words of a heading yields the words (with their inline marks, like `**bold**`), never a stray `#`, and a partial copy from a code block yields the plain code, never fences. Rich-text apps still paste formatting — the rich (HTML) flavor is written alongside, exactly as before. Set `birta.copyFormat` to `"richText"` to restore the old plain-text rendition; the setting applies to open editors immediately.
- **A little more air under headings** — the space between a heading and the content it opens grew slightly (the shared spacing token behind every heading level, not a per-case tweak), so a list directly under a heading — whose text also shifts right past its markers — no longer reads cramped against the heading's baseline. Headings still sit visibly closer to their own section than to the block above.
- **The block palette leads with the selection's type** — selecting whole blocks raises the floating palette, whose leading button (the one that opens the full block menu) now shows the selected blocks' own gutter symbol whenever every block in the selection is the same kind: a bullet, ordered, or task list shows its list icon, a heading its H1–H6 badge, a paragraph its pilcrow. A mixed selection keeps the neutral grip.
- **⌘⇧↑/↓ now extends the selection instead of moving the block** — on macOS that means select to the start/end of the document, matching VS Code's raw editor and every native text field; on Windows/Linux, Ctrl+Shift+↑/↓ likewise regains its platform's native selection meaning. It was previously a second binding for moving the selected block, shadowing the native selection chord; moving blocks stays on ⌥↑/↓ (and the block menu, drag handle, and the Move Block Up/Down palette commands). With whole blocks selected (Escape / marquee), the chord selects from those blocks to the document's start or end.
- **Keyboard Shortcuts panel is now a true inventory** — it lists only the fixed, always-accurate shortcuts (labels left, keys right-aligned), and the **Edit Keyboard Shortcuts** button sits in a fixed footer below the scrolling list (nothing scrolls under or past it), and scrolling the panel no longer spills over into the document. The old names-only "customizable commands" listing is gone: those keys live in — and may be rebound via — VS Code's own Keyboard Shortcuts UI, which the button opens.
- **Show Block Handles left the display (A) toolbar menu** — the `birta.blockHandles` setting (and its palette commands) still work; the three radio rows were too prominent for a rarely-changed preference.
- **The sidebar is wider by default and can't be crushed** — default width 260px (was 220), minimum 240px (was 150). When the visible tabs don't fit the strip, they collapse into a **dropdown showing the active tab** (opening a menu of the rest) instead of clipping or wrapping — the flip/hide buttons never move from the top-right corner.
- **Menu group headers share one typographic voice** — the slash menu, block menu, and toolbar dropdown section headers now use the same heading grade as the sidebar's group headers (title case, full foreground), replacing four hand-rolled all-caps caption styles.
- **The display (A) menu slimmed down** — the **Font settings** entry joined Show Block Handles in Settings-only territory; the menu keeps the frequent moves (size, width, family).

- **Reordering a heading in the outline now sets its level to match where you drop it** — the table of contents is a structural editor as well as a view, so a drop's position decides the section's rank. Drop **onto** a heading to make the section its child (a heading dropped onto an H3 becomes an H4); drop on the **line between** headings to make it a sibling of the heading below (terminal position: of the last section). The section's whole subtree moves with it and shifts by the same amount, so its internal hierarchy is preserved; levels that would pass H6 stop there. A drop whose position already matches the section's level leaves it untouched, and the whole thing is a single undo step. Dropping onto a **collapsed** section works like any other drop — it files the section inside and the fold opens to show it where it landed, so nothing you move is ever left out of sight. Dragging a heading's gutter handle **in the document** is unchanged — that stays a literal move, because the text is text and the outline is the structure.
- **Typing in very large documents is noticeably lighter** — with the outline panel showing, every keystroke used to recompute the whole table of contents even when the edit couldn't have changed it. Ordinary typing in body text now skips that recomputation (measured: about a third less total typing stall on a 300 KB document), while edits that do touch a heading — retyping its text, adding, deleting, or converting one — still update the outline instantly.
- **Opening a long document is noticeably faster** — the fold chevrons and block handles that sit in the gutter of every heading used to be built while the editor was still coming up, so a document with many headings was slower to appear. On a fresh open (nothing folded) they now settle in just after the text first paints rather than blocking it — measured about a quarter faster to first paint on a 140-heading document. Folding behaves exactly as before; the gutter affordances simply arrive a moment after the text, the way proofreading marks already do. A document opened with folds still collapses them before the first paint, so nothing flashes.
- **Every document opens faster, code or not** — about 110 KB less code is loaded before the editor appears. Two things were being paid for on every open regardless of the document: a second, unconditional copy of ~35 syntax-highlighting grammars (the on-demand set already covered them), and the sanitizer behind inline HTML — `<sub>`, `<br>`, and friends — which now loads only when a document actually contains raw tags, the way math and diagrams already do. Highlighting and inline HTML render exactly as before; an inline tag paints a fraction of a second after the text the first time one appears in a document.
- **The extension now ships under the Birta Labs publisher** — the qualified id is `BirtaLabs.birta-writer` (was `harlanlewis.birta-writer`, which only ever existed as local VSIX sideloads, never a marketplace listing). If you sideloaded an earlier build, install the new one and remove the old copy so only one editor claims `.md` files; your `birta.*` settings are untouched by the switch.
- **Nesting one `:::` directive inside another survives a save** — moving a `:::note`/`:::info` admonition into another directive now writes the outer fence longer than the inner (`::::` around `:::`, the CommonMark convention), so the inner block reopens as a directive instead of flattening to plain text.
- **Moving a horizontal rule to the top of a directive keeps it a rule** — a `---` dropped directly under a directive's opening fence used to reopen as a heading (the fence line became setext-underlined), destroying both the rule and the directive; the rule now stays a rule.
- **Moving a horizontal rule to the top of a callout keeps it a rule** — the same reopen hazard as the directive case: a `---` dropped directly under a callout's `> [!NOTE]` marker line turned the marker into a heading and destroyed the rule. The callout now separates them the way directives already did.
- **Moving a block between callouts no longer splits the callout on reopen** — dragging a paragraph out of one callout (or blockquote) and into another used to leave a stale blank line where the emptied callout sat, so on reload the destination callout was split in two and the moved block landed in a plain blockquote. The moved block now reopens inside the callout it was dropped into.
- **Moving a block no longer corrupts an escaped `\==highlight==`** — a hand-escaped highlight literal (`\==not a highlight==`) kept as plain text now re-serializes with its backslash intact when its block is moved, instead of silently dropping the `==` bytes and turning into a highlight on reopen.
- **Editing chords no longer change an unfocused document** — with the editor as the active tab but focus in the Explorer/sidebar, pressing a document-mutating shortcut (⌘⇧K delete block, ⌃J join lines, the list/heading/paragraph chords, ⌘K link) used to edit the document you weren't looking at. These chords now require the editor itself to be focused; find, fold, and navigation shortcuts are unchanged.
- **The numbered-list block handle no longer hides under multi-digit numbers** — on a list reaching item 10+ (or at 150–200% content scale) the grabber sat on top of the number as an invisible click target. It now tracks the number's width and the content font size, staying clear of the ink.
- **The table of contents width is now a `birta.tocWidth` setting** — dragging the panel's edge already remembered the width, but it lived in hidden extension state. It's now an ordinary setting: editable in `settings.json`, scopeable per-workspace, carried by Settings Sync, and echoed live to every open editor when changed. Dragging still updates it as before. (This puts all four ToC preferences — `tocPosition`, `tocAutoHideThreshold`, `tocVisibility`, `tocWidth` — in the same place.)
- **The slash command menu now opens inside headings** — typing `/` in a heading did nothing (the heading's own text normalization silently suppressed the menu right after the keystroke). It now opens the same insert menu it does in a paragraph.
- **Blocks nested inside a list item now have a grabber** — a blockquote, code block, callout, table, or heading indented under a list item had no gutter handle at all, so its block menu and drag handle were unreachable. It now shows its own marker like the same block nested anywhere else; click it for the menu or drag it to move the block.
- **List grabbers inside a callout, quote, or directive no longer overlap the accent bar** — a list nested in one of those containers drew its per-item handles on top of the container's colored bar. The handles now step clear of every enclosing bar, at any content font size.
- **Drag auto-scroll stays smooth on very long documents, and starts where the text does** — holding a drag near the top or bottom edge scrolls the document, and on a long one that scroll had been degrading badly: on a synthetic 15,000-block document it managed about 5 frames a second, so the drop line lurched instead of tracking the pointer (it was recomputing every block's position on every frame, when scrolling moves them all by the same amount). It now holds a steady 60 frames a second at that size — around eight times the travel for the same gesture — and is unchanged on documents that were already smooth. Separately, the top scroll band now begins at the toolbar's lower edge rather than the very top of the window, so the drag no longer starts creeping upward while the pointer is still well inside the text; when the toolbar is hidden, nothing changes. Both apply to every drag in the editor — blocks, table of contents entries, the margin marquee, and dropped images.
- **Diagrams fit at up to 100% and follow the pane** — fit-to-view no longer enlarges a small Mermaid diagram past its natural size to fill the preview (inline and fullscreen alike); zoom in manually when you want it bigger. Diagrams also refit automatically when the editor pane is resized — unless you've panned or zoomed by hand, in which case your view is left alone.
- **A dragged-in image shows where it will land** — dropping an image file already put it under the pointer rather than at the cursor, but nothing showed you where that was, and it went in at the exact spot underneath — which is mid-sentence as often as not. The drag now draws the same accent insertion line a block drag and a table-of-contents drag draw, snapped to the boundary between blocks nearest the pointer, and the image lands on that line as a block of its own. Holding the drag near the top or bottom edge scrolls the document at the same accelerating rate a block drag does, so the drop isn't limited to what's on screen when you start. **Hold ⇧ while you drag.** That requirement is VS Code's, not ours — dropping a file *into* any editor rather than opening it as a new tab is gated on ⇧ for every editor, the workbench paints its own full-width "Hold ⇧ to drop into editor" banner while you drag, and an extension has no way to waive it; without ⇧ the file opens in a new tab exactly as before. Pasting an image (⌘V) has never needed a modifier and still inserts at the cursor.

### Removed

- The ` ```calca ` fence alias for calculation blocks — write ` ```calc ` or ` ```calculation `; an existing ` ```calca ` fence renders as an ordinary code block.

### Security

- **Network consent is now user-level only** — the settings that let the editor touch the network or write fetched content into a file (`birta.network.enabled`, `birta.embeds.enabled`, `birta.pasteUnfurl.enabled`, `birta.pasteUnfurl.autoApply`) can no longer be set from a workspace's `.vscode/settings.json`. Previously a repository you opened could quietly enable them for you; now only your own user settings decide, and the offline-by-default guarantee holds regardless of what a workspace ships. Accepting an in-editor "Enable" prompt likewise always records your choice in your user settings, never in a workspace file.
- **Embed players run in a sandboxed frame** — the click-to-load player iframe (YouTube, Loom, Figma) now carries a minimal capability sandbox: the framed page can run its player but cannot navigate your editor, submit forms, trigger downloads, or write to your clipboard. What hosts may be framed was already pinned by the content-security-policy; this pins what a framed page may do.

## [0.2.3] - 2026-07-04

A large batch focused on round-trip fidelity, VS Code parity, and Markdown syntax breadth.

### Added

- **Math (KaTeX)**: inline `$…$` and block `$$…$$` math render in place. Click inline math to edit its source in a popover; block math toggles between source and a rendered preview like code blocks. The KaTeX engine loads lazily so it costs nothing on documents without math.
- **Footnotes**: `[^label]` references render as superscript chips with a hover preview of the definition and click-to-jump; definitions are editable in place with a back-link to the first reference. An "Insert Footnote" toolbar button auto-numbers.
- **Source-based find & replace**: find now searches the Markdown *source* — link URLs, image paths and alt text, and code-fence languages are matchable — with regex and whole-word toggles alongside case sensitivity, and `$1…$n` capture-group substitution.
- **Command palette & context menu**: all editor actions (formatting, insert table/link/image/math/footnote/HR, headings, lists, find, frontmatter, TOC) are now Command Palette commands, and right-click offers table row/column operations, edit link, and copy-as-HTML/Markdown.
- **Heading outline / Go-to-Symbol**: `Cmd/Ctrl+Shift+O` opens a heading quick-pick for the WYSIWYG document.
- **Responsive toolbar**: in narrow panes, overflowing toolbar groups collapse into a `⋯` menu instead of clipping.

### Changed

- **Native text-document editor (CustomTextEditorProvider)**: the WYSIWYG editor is now backed by VS Code's own `TextDocument` instead of reading and writing the file itself. This brings the standard editor experience:
  - **Native undo/redo**: Cmd/Ctrl+Z and Shift+Cmd/Ctrl+Z now use VS Code's document history and stay in sync with edits made in a side-by-side text view.
  - **Native dirty state**: the tab shows VS Code's unsaved-changes dot and participates in Save All, hot exit, and "revert file" like any text editor. The extension's own `markdownWysiwyg.autoSave` / `autoSaveDelay` settings are deprecated in favor of the built-in `files.autoSave`, which the editor now honors.
  - **Git integration**: because edits flow through the document, staging, diffing, discarding changes, and `git checkout` update the editor live.
- **Cursor-preserving inbound sync**: external changes (a side-by-side text edit, undo/redo, git operations, hot-exit restore) are applied to the editor as a minimal ProseMirror diff rather than a full rebuild, so the caret and selection survive edits made elsewhere in the document. Falls back to a full rebuild if the diff can't be applied cleanly.
- **Source-style preservation**: setext (underlined) headings, `***`/`___` thematic-break markers, and `_`/`*` emphasis markers now round-trip in their original style instead of being canonicalized on edit.
- **English-first UI**: remaining hardcoded Chinese strings were swept into the i18n layer (English as the base language), with a CI guard preventing regressions.

### Fixed

- **Formatted links no longer split**: a link whose text contains bold/italic/code (e.g. ``[**bold** and `code`](url)``) previously shattered into several adjacent links when its line was edited; it now serializes as a single link. Also root-fixes the related strong-around-link splitting.
- **Line breaks inside table cells**: `<br>` in a GFM table cell is preserved instead of being silently flattened to a space on save; Shift+Enter inserts one.
- **Remote/SSH/WSL/Codespaces**, **Cmd+B/Cmd+I no longer leak to VS Code**, **undo inside overlay inputs**, and **lossless frontmatter editing** (earlier Phase 0 fidelity fixes).
